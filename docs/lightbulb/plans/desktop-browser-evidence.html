The desktop launch test in this planning session used a 45-second timeout. It reached renderer startup and sidecar ready before the timeout killed the process. GPU errors appeared during forced shutdown, so they should not be treated as the initial desktop blocker without a reproduction from a non-timeout run.

Architecture Theories Reviewed

Theory Pros Cons Decision
Require global agent-browser Fast. Matches existing AGENTS browser automation guidance. Brittle. New machines fail silently until the model tries to use the browser tool. Use as a supported backend, not the only UX.
Bundle or configure browser backend Reproducible. Lets Desktop show a clear missing-backend state and install/run guidance. Needs platform-specific install behavior and careful security messaging. Choose this for the product slice.
Use Playwright as the local backend Already a repo dependency for app e2e tests. Good screenshots and traces. Different command surface than agent-browser; risks duplicating tooling. Keep as test/evidence harness, not the default tool backend.
Use only Firecrawl or Steel remote sessions Live view and CDP URLs are strong evidence artifacts. Requires secrets and external service availability. Support as optional providers; do not make local proof depend on them.

Evidence Flow

DesktopElectron starts the renderer and local sidecar server.
Browser ToolSession tool registry exposes browser to agents.
BackendLocal agent-browser, Steel, or Firecrawl executes browser action.
ArtifactScreenshot path, live view, interactive view, CDP URL, or attachment is returned.
App Surface/browser summarizes sessions, activity, providers, and evidence count.

Detailed Steps For PR A

1. Preserve artifact safety
Keep screenshot paths relative to the active instance. Core tests should change cwd to a temp directory instead of requesting external absolute paths. Opencode registry tests should continue proving that ../escape.png is rejected.
2. Add backend health
Add a small browser backend probe that checks whether agent-browser is available and reports the exact command that failed. Surface that result in /browser next to "Tool Available" so users can distinguish "tool registered" from "backend runnable".
3. Document install choices
Update packages/desktop/README.md and Lightbulb docs with the real desktop run command, common Linux fallback ELECTRON_DISABLE_GPU=1, and local browser backend setup. Include Firecrawl/Steel as optional remote backends.
4. Capture visual evidence
Start Desktop or the app/backend dev pair, open /browser, and capture a screenshot. If agent-browser is installed, also run a screenshot action and verify it appears in Browser Activity.
5. Keep PR small
Do not combine with traceable-loop schema migrations. This PR should make computer-use evidence reliable enough for future Lightbulb PRs to use as a gate.
