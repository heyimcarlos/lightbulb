# Implementation Plan: Lightbulb Bootstrap Spine

## Overview

This plan turns the OpenCode fork into the first inspectable Lightbulb harness slice: durable account work state, a dashboard route, and artifact lineage from worker output back into parent orchestration.

## Phase 1: Repo and workflow bootstrap

- Configure Matt Pocock-style issue tracker docs under `docs/agents/`.
- Create PRD/ADR/domain docs under `docs/lightbulb/`.
- Create initial GitHub PRD and vertical-slice issues.
- Verification: `gh label list --repo heyimcarlos/lightbulb`, `gh issue list --repo heyimcarlos/lightbulb`.

## Phase 2: Schema tracer bullet

- Add Lightbulb-prefixed tables for account, goal, loop, run, worker, task packet, artifact, artifact edge, gate, event.
- Add seed/dev command or test fixture that creates one goal → loop → run → worker → artifact.
- Verification: package-local typecheck plus a focused persistence test.

## Phase 3: Dashboard tracer bullet

- Add a TUI route or panel that displays seeded Lightbulb account state.
- Show active loops, workers, inbox/gates, and artifacts.
- Verification: package-local typecheck and snapshot/behavior test if existing TUI test seam supports it.

## Phase 4: Worker/artifact flow

- Add a minimal task packet to worker lifecycle seam.
- Register a local artifact generated by a worker run.
- Parent view receives summary and artifact handle.
- Verification: behavior test covers produce/consume lineage and status transitions.

## Phase 5: Context/gate policy

- Add configurable thresholds for context/cost/gate status.
- Make the loop stop/checkpoint/delegate when threshold is crossed.
- Verification: policy transition tests with no model call dependency.
