# Lightbulb GitHub Project Triage

Use this for Lightbulb/openbulb GitHub issue and PR stewardship.

## Local Gate

Start from the current repo unless the user names another one.

```bash
git status --short --branch
git branch --show-current
gh repo view --json nameWithOwner,url,defaultBranchRef
```

The default branch is `dev`; do not assume `main` exists. If the worktree is dirty, identify the dirty files and protect unrelated changes.

## Queue Scan

Always surface full URLs for issues and PRs.

```bash
repo=$(gh repo view --json nameWithOwner --jq .nameWithOwner)
gh issue list --repo "$repo" --state open --limit 100 \
  --json number,title,author,labels,createdAt,updatedAt,url
gh pr list --repo "$repo" --state open --limit 100 \
  --json number,title,author,isDraft,reviewDecision,mergeStateStatus,statusCheckRollup,createdAt,updatedAt,url
```

For ambiguous or actionable items, read full detail:

```bash
gh issue view <number> --repo "$repo" --comments \
  --json number,title,author,body,comments,labels,createdAt,updatedAt,url,state,stateReason
gh pr view <number> --repo "$repo" \
  --json number,title,author,body,comments,files,commits,isDraft,reviewDecision,mergeStateStatus,statusCheckRollup,url
```

## Classification

Return these buckets:

- `Autonomous`: bounded implementation or cleanup, clear owner intent, safe verification path, no missing credentials.
- `Needs human`: product choice, security/privacy decision, missing live access, release authorization, or destructive action.
- `Blocked`: real dependency, red CI without fix permission, merge conflict, missing branch, or unavailable environment.
- `Ready to close/merge`: merged, or mergeable with direct evidence, passing focused verification, current-head green or explicitly waived checks, current-head approval/Codex review when required by the active workflow, and no unresolved requested changes.
- `Defer/wontfix candidate`: already covered, obsolete, superseded, or outside Lightbulb direction.

Use only the configured setup labels: category labels `bug` / `enhancement`, plus state labels `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, and `wontfix`. Do not introduce Lightbulb domain or worker-status labels.

## Completion Triage

Do not close from title or branch name alone.

Before calling an issue complete:

- confirm linked PR or local branch evidence
- inspect relevant files and behavior
- run the focused package-local verification
- post a proof comment when mutating GitHub:
  `> *This was generated by AI during triage.*`
- close with completed reason only after the evidence matches the issue contract
- re-read the issue and confirm final state

## Autonomous Work Mode

When the user asks to keep going autonomously, process one issue/PR at a time.

1. Pick the highest-confidence autonomous item.
2. Create or reuse a short `dev`-based branch/worktree.
3. Implement the smallest durable slice.
4. Verify with focused tests, typecheck when relevant, and `git diff --check`.
5. Prepare a PR or exact handoff only when push/PR permission exists.
6. Return to the queue after the item is clean, blocked, or decision-ready.

For Lightbulb loop/orchestration work, prefer artifacts and event/run/gate evidence over raw transcripts.
